# Localization via react-intl with message-id fallback

The site is built from a design mockup whose copy is not yet finalized, so we standardize on FormatJS (react-intl) with `{ "key": "value" }` JSON locale files. We ship Russian (`ru-RU.json`) as the default — the studio's primary audience — with Hebrew (`he-IL.json`, right-to-left) as the second locale the header switcher offers, and infrastructure that supports three locales (the third, `en-US.json`, is kept complete but not yet exposed). When a message key is missing from the active locale file, we render the message id itself rather than silently showing an empty string or falling back to another language.

The id-display fallback is deliberate: because copy authoring is deferred, the ids serve double duty as an incomplete-content checklist. Ids are sectioned and semantic (e.g. `footer.contact.phone`) so the fallback text reads like a to-do list. This is surprising without context — a future reader might "fix" it to render nothing or fall back to English — so we record it here rather than let it look like a bug.
